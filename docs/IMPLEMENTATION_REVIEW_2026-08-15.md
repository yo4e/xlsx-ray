# Implementation Review and Product Decision — 2026-08-15

## Scope and method

This review re-examined the merged v0.1 implementation rather than accepting its original tests as proof of readiness. The review covered OOXML ZIP/XML parsing, relationship resolution, formula normalization and impact evidence, deterministic rendering, CLI exit behavior, the composite Action, package artifacts, and CI. It added synthetic adversarial fixtures and one workbook generated by `openpyxl`; it did not claim compatibility with the complete Excel feature set or every third-party producer.

## Findings and dispositions

| Area | Finding | Disposition |
|---|---|---|
| Formula normalization | Removing whitespace outside strings was unsafe: Excel whitespace can represent range intersection. | Fixed. v0.1 normalizes only function-name casing outside string literals; it preserves all whitespace. |
| Formula-impact evidence | The previous direct-reference pattern missed bare A1 references, reported references inside string literals, and did not correlate `$A$1`, `A1`, case variants, or quoted sheet names reliably. | Fixed. Direct A1 references are extracted outside string literals and canonically correlated for review evidence only. |
| OPC relationship targets | Valid workbooks produced by `openpyxl` can use `/xl/...` internal target form; overly narrow target handling rejected them. | Fixed. Safe `/xl/...` and standard relative targets are accepted, while external, ambiguous, escaping, and missing worksheet targets fail closed. |
| Fixture generation | XML attribute quote characters in the synthetic builder were not escaped. | Fixed. Fixture attributes now escape quote characters, enabling realistic list-validation cases. |
| ZIP ambiguity | A dict-based member map silently discarded duplicate ZIP names. | Fixed. Duplicate member names are rejected before inspection. |
| XML resource handling | The original parser bounded raw part size but did not bound element count, nesting, or aggregate parsed text. | Fixed. v0.1 now applies explicit depth, element-count, and text limits before interpretation. |
| Error semantics | A missing worksheet relationship previously produced a partial report warning. | Fixed. A report that omits a declared worksheet is ambiguous, so malformed worksheet relationship graphs now reject the workbook with CLI exit code 2. |
| CI/action readiness | Unit tests did not exercise the repository composite Action, and the workflows used Node 20-era actions. | Fixed. CI uses checkout v5/setup-python v6 and exercises the local composite Action against generated fixtures. The example uses Node 24-compatible checkout/upload-artifact versions. |

## What is trustworthy enough for the release candidate

The supported v0.1 facts are deterministic package facts: sheet add/remove and high-confidence part-path rename evidence; raw cell value/formula text; defined-name text; external relationship targets; canonical validation/protection facts; and VBA package presence. The CLI's Markdown/JSON ordering and `--fail-on` threshold are covered by repeated-run, fixture, built-wheel, and CI checks.

Formula-impact entries are useful reviewer leads, not dependency-analysis conclusions. They are reliable only for direct A1 syntax outside literals, after case and absolute-marker normalization. They do not establish formula correctness or downstream calculation results.

## Explicitly unsupported claims

XLSX-Ray must not claim Excel recalculation, formula semantic equivalence, full dependency analysis, macro parsing/security review, external workbook resolution, chart/pivot semantic diffing, style/layout comparison, encrypted package support, or safe handling of hostile inputs outside a suitably isolated execution environment. See [COMPATIBILITY.md](COMPATIBILITY.md) and [SECURITY.md](../SECURITY.md).

## Competitive re-check

The implementation evidence strengthens, rather than invalidates, the original differentiation. The closely related tools found in the original research remain cell/text-comparison or add-in oriented, while XLSX-Ray now demonstrates a narrow package-fact/risk-review layer that is local, deterministic, no-API, and CI-ready. The refreshed competitor record remains in [RESEARCH_REFRESH_NOTES.md](RESEARCH_REFRESH_NOTES.md), including the implementation-time inspection of [excel-diff](https://github.com/bitterjug/excel-diff), [excel-compare](https://github.com/yarhamjohn/excel-compare), [ExceLint](https://github.com/ExceLint/ExceLint), [ExcelCompare](https://github.com/na-ka-na/ExcelCompare), and [Git XL](https://github.com/xltrail/git-xl). ## Decision: GO, with a narrow review-audit focus

**GO** is justified for an untagged `0.1.0` release candidate. The tool demonstrably produces review evidence that normal Git binary diffs do not: a formula rewrite, removed validation, new link, protection change, and macro package presence are reported as distinct, explainable facts. The product should remain intentionally narrow rather than pivoting toward an Excel engine.

| Next capability | User value | Engineering confidence | Recommendation |
|---|---:|---:|---|
| Formula impact for named references and range overlap, explicitly evidence-only | High | Medium | Next substantial task. Maintain the non-calculating boundary. |
| First-class Git base-ref discovery for changed workbook paths | High | Medium | Consider after user feedback; preserve explicit-path mode. |
| Stable chart/pivot presence inventory with no semantic claim | Medium | High | Small follow-up if reviewers request it. |
| Styles, conditional formatting, calculation, VBA parsing, or AI scoring | Mixed | Low | Do not prioritize for v0.1. |

The recommended next large autonomous task is **evidence-only named-reference and range-overlap impact indexing**, preceded by a representative fixture study. It expands a demonstrated review workflow without requiring formula execution, external services, or opaque scoring.
