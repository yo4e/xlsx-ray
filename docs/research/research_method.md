# OSS Opportunity Research — Method

調査日: 2026-08-15（ユーザーのタイムゾーン）

## 目的
需要が実証され、現行OSSに明確な未充足があり、少人数でローカル優先のMVPを構築できる新規OSS機会を特定する。

## 採点軸
各候補を 1（弱い）〜5（強い）で採点する。総合点は、需要の強さ 35%、競合の弱さ 25%、開発容易性 20%、OSSとしての拡散性 20% の加重平均（100点換算）とする。

- 需要の強さ: 複数の独立コミュニティ投稿、Issue、検索・ダウンロード・利用指標、または普及済み有料製品で検証する。
- 競合の弱さ: 活発な強力OSSが機能を満たしている場合は低くする。放置・導入摩擦・非ローカル・精度/UXの穴がある場合は高くする。
- 開発容易性: 1〜3人が3か月程度で有用なMVPを提供できるかで評価する。学習済みモデル訓練、常時クラウド、巨大なコネクタ網は減点する。
- OSS拡散性: CLI、ライブラリ、GitHub Action、VS Code拡張など、再利用・PR・プラグイン・テンプレートが生じやすいかを評価する。

## エビデンスの優先順位
1. 公式リポジトリ、パッケージレジストリ、公式Issue/Discussion、仕様。
2. GitHub APIによるスター、フォーク、更新日時、オープンIssue数。
3. Stack Overflow、Hacker News、Reddit等の一次的な利用者の困りごと。
4. 商用製品の価格・機能ページ（問題に対する支払い意思の補助証拠）。

数値は取得時点のスナップショットであり、スター数単独は需要の十分条件としない。各機会は、需要の量的または反復的なシグナルと、競合への具体的不満の双方を確認して採否を決める。

## 除外方針
強力かつ活発なOSSが低コストで主要用途を満たす場合、たとえ需要が大きくても原則NOとする。単純なLLMラッパー、予測・投機助言、継続的に高額な外部API依存を要する案は除外または大幅減点する。
