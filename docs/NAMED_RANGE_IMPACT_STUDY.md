# Named-reference and Range-overlap Fixture Study

## Purpose

This study defines the narrow subset of formula-impact evidence that XLSX-Ray can report without calculating Excel formulas or claiming a complete dependency graph. All fixtures are generated from code. The final regression suite includes both the repository's controlled OOXML fixture writer and a workbook generated by `openpyxl`.

> **Interpretation rule:** a match is a reviewer lead based on static formula text and a static OOXML defined-name expression. It is not proof of an evaluated value, a complete dependency path, or Excel semantic equivalence.

## Fixture matrix and decision

| Fixture case | Static recognition result | Decision | Evidence behavior |
|---|---|---|---|
| Workbook-scoped name → one sheet-qualified A1 cell | Deterministic name lookup and point containment | Supported | `defined_name` lead when a formula resolves the name and the changed cell is the target. |
| Workbook-scoped name → one sheet-qualified A1 range | Deterministic range containment | Supported | `defined_name` lead when the changed cell lies in the resolved inclusive range. |
| Local name that shadows a workbook name | Deterministic when the formula cell's sheet scope is known | Supported | Resolve local scope first; do not attribute the workbook name on that sheet. |
| Local name on another sheet | Scope is not active for the formula cell | Supported as non-match | Do not guess that it is visible. |
| Quoted sheet names and absolute/mixed markers | Already represented in supported direct A1 syntax | Supported | Normalize case and `$` markers for containment; preserve original reference as provenance. |
| Direct A1 range containing the changed cell | Inclusive row/column interval is deterministic | Supported | `range_overlap` lead. |
| Direct A1 range touching or outside the changed cell | No interval containment | Supported as non-match | No lead. |
| Cross-sheet direct range | Deterministic when the sheet is explicitly named | Supported | `range_overlap` lead only for the matching sheet. |
| Formula strings containing A1/name-looking text | Literals can be removed without parsing formula semantics | Supported as non-match | No named/range lead from text inside double quotes. |
| Reordered defined-name XML elements | Name identity is key/scope based, not XML order based | Supported | Stable output. |
| Name without an explicit sheet-qualified static A1 target | Context can be relative or expression-based | Unsupported | No lead; limitation remains explicit. |
| Name expression using formula operators/functions, unions, intersections, constants, or multiple areas | Static target set is not uniquely determined by the narrow parser | Unsupported | No lead; report/JSON never claims resolution. |
| `INDIRECT`, structured references, 3D references, spill syntax, and external-workbook names | Dynamic, context-sensitive, or external semantics | Unsupported | No named/range lead from the construct. |

## Chosen representation

A change continues to expose the legacy flat `impact` list of formula-cell addresses for compatibility. It additionally exposes ordered `impact_evidence` records. Each record contains the flagged formula cell, a kind (`direct_a1`, `range_overlap`, or `defined_name`), original reference text, the resolved static range where applicable, and evidence-only wording. The parent change's `subject` remains the changed source fact/cell.

The JSON schema version advances from `0.1` to `0.2` because `impact_evidence` is a deliberate, machine-readable extension. Existing consumers can keep using `impact`; consumers requiring provenance should use `impact_evidence` and check the schema version.

## Scope-resolution policy

For a formula in worksheet **S**, XLSX-Ray resolves an unqualified name by looking for a local name whose `localSheetId` maps to **S**. If none is present, it considers the workbook-scoped name. A local name on any other worksheet is not considered. A defined-name expression is eligible only when its entire expression is a single sheet-qualified A1 cell or A1 range and contains no external workbook marker.

## Residual risks

The narrow parser can intentionally miss valid Excel dependencies that use unsupported syntax. This produces false negatives by design. False positives are constrained by requiring a known name identity, active scope, an entire supported static defined-name expression, and point-in-range containment; however, the result is still not a guarantee of Excel's calculated dependency behavior.
